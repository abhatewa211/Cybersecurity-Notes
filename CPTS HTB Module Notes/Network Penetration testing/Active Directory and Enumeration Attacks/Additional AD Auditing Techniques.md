## 1. Introduction to AD Auditing

Along with **hardening an Active Directory domain**, AD auditing is important because it provides evidence of potential security issues.

The purpose of AD auditing is to:

- Gather detailed information about the AD environment.
    
- Identify potential security issues and misconfigurations.
    
- Provide evidence that a problem exists.
    
- Help customers understand the severity and impact of issues.
    
- Support remediation and security improvements.
    
- Produce useful visualizations and reports.
    

The module focuses on several tools that can provide different types of AD data and visualizations.

### Main tools covered

|Tool|Main Purpose|
|---|---|
|**AD Explorer**|Browse AD and create snapshots|
|**PingCastle**|Assess AD security posture|
|**Group3r**|Audit Group Policy|
|**ADRecon**|Collect large amounts of AD information|

**AD Explorer** is part of the **Sysinternals Suite**.

It is an advanced Active Directory viewer and editor that allows us to:

- Navigate the AD database.
    
- Define favorite locations.
    
- View object properties.
    
- View object attributes.
    
- Edit permissions.
    
- View an object's schema.
    
- Perform sophisticated searches.
    
- Save searches for later use.
    

### Why AD Explorer is useful

One of the most important features for auditing is the ability to create **AD snapshots**.

A snapshot allows us to save the state of Active Directory at a specific point in time.

This can then be used for:

- Offline analysis.
    
- Reporting.
    
- Historical comparison.
    
- Before-and-after comparisons.
    
- Identifying changes in AD objects.
    
- Identifying changes in attributes.
    
- Identifying changes in security permissions.

## 3. Logging in with AD Explorer

When AD Explorer starts, we can either:

1. Enter credentials and connect to Active Directory.
    
2. Load a previously created snapshot.
    

The module notes that **any valid domain user** can be used to log in.

### AD Explorer workflow

```text
Start AD Explorer
       ↓
Enter domain credentials
       ↓
Connect to Active Directory
       ↓
Browse AD objects
       ↓
View properties / attributes
       ↓
Create snapshot
       ↓
Analyze snapshot offline
```

Once connected, we can browse Active Directory and examine information about its objects.

# 4. Creating an AD Snapshot

To create a snapshot:

```text
File → Create Snapshot
```

Then provide a name for the snapshot.

After creation, the snapshot can be moved offline and analyzed later.

### Important concept

**AD Snapshot = Point-in-time copy of AD information**

This makes it possible to compare:

```text
Snapshot A
   ↓
Earlier state

        VS

Snapshot B
   ↓
Later state
```

The comparison can reveal:

- New objects.
    
- Deleted/changed objects.
    
- Attribute changes.
    
- Permission changes.

**PingCastle** is a tool used to evaluate the **security posture of an Active Directory environment**.

It presents information through:

- Maps.
    
- Graphs.
    
- Reports.
    
- Security assessments.
    

It can also help build an inventory of hosts in an enterprise through a readable domain map.

### PingCastle vs PowerView/BloodHound

According to the module, PingCastle is different because it doesn't only provide enumeration information.

It also provides a **detailed report of the target domain's security level** using a risk-assessment/maturity framework.

Its scoring methodology is based on **CMMI — Capability Maturity Model Integration**.

# 13. Understanding Group3r Output

When reading Group3r output, **indentation represents different levels**.

```text
GPO
│
├── Policy Setting
│      │
│      └── Finding
│
```

Specifically:

- **No indentation** → GPO.
    
- **One indentation level** → Policy settings.
    
- **Another indentation level** → Findings within those settings.
    

### Group3r Finding

A finding provides:

- A link to the relevant policy setting.
    
- The interesting portion of the setting.
    
- A reason explaining why it was identified as a finding.
    

The module emphasizes that Group3r can uncover interesting paths or objects that other tools may overlook.

The overall objective isn't simply collecting information. The module emphasizes that the actions performed during an assessment should have a purpose, with the ultimate goal of improving the customer's security posture.

# 20. Important Points to Remember

### AD Explorer

- Part of **Sysinternals Suite**.
    
- Used to browse AD.
    
- Can view object properties and attributes.
    
- Can edit permissions.
    
- Can perform searches.
    
- Can create **AD snapshots**.
    
- Snapshots can be compared to identify changes.
    

### PingCastle

- Assesses AD security posture.
    
- Produces maps, graphs and reports.
    
- Uses a risk-assessment/maturity approach.
    
- Uses **CMMI** for its scoring methodology.
    
- `healthcheck` provides a baseline overview.
    
- Can examine areas such as trusts, shares, permissions, users and computers.
    
- Scanner contains multiple security checks.
    

### Group3r

- Focused on **Group Policy**.
    
- Requires a domain-joined host/domain-user context.
    
- Administrator privileges are not required.
    
- `-s` → stdout.
    
- `-f` → file output.
    
- Indentation indicates GPO → policy setting → finding.
    

### ADRecon

- Collects a large amount of AD information.
    
- Particularly useful when stealth isn't required.
    
- Collects domain, forest, trusts, users, SPNs, groups, GPOs, DNS, computers and other information.
    
- Some information requires privileged access.
    
- Produces CSV data and can generate HTML/GPO reports.
    
- `-GenExcel` can be used later to generate an Excel report.
